VPN POLICE
On patrol
Case No. 0417 — Open

Your WiFi isn't the culprit. Your VPN is.

FortiClient sometimes still says "Connected" even after your internet has actually stopped working. VPN Police notices that first, and disconnects it for you.

Field Notes● Active

Your internet drops sometimes — that's just normal. The problem is your VPN not noticing. So this quietly checks in the background, and turns the VPN off the moment your internet is really down.

The Patrol
STEP 01
Patrols
Pings google.com every 15 seconds.
STEP 02
Confirms
Waits for three drops in a row.
STEP 03
Responds
Disconnects the VPN, then radios you.
The Rulebook
Permitted
  • Checking google.com every 15 seconds
  • Waiting for a real drop, not one blip
  • Disconnecting your VPN, once per drop
  • Notifying you the moment it acts
Forbidden
  • Sending anything anywhere
  • Requesting admin or root access
  • Touching anything but this one VPN
  • Acting twice on the same drop
Choose Your Officer
The Beat Copsimplest

Drops the VPN when the network dies. You reconnect it yourself.

# one paste — writes the file, then runs it
cat > install-disconnect-only.sh << 'INSTALL_EOF'
#!/bin/bash
# VERSION 1 — disconnect only.
# Watches the network. On a real drop (3 consecutive failed pings), disconnects
# the FortiClient VPN. Does NOT reconnect it automatically — you reconnect by hand.
set -e

WD_DIR="$HOME/vpn-watchdog"
LABEL="com.vpnpolice.agent"
PLIST="$HOME/Library/LaunchAgents/$LABEL.plist"

mkdir -p "$WD_DIR"
touch "$WD_DIR/watchdog.log"

cat > "$WD_DIR/watchdog.sh" << 'SCRIPT_EOF'
#!/bin/bash

HOST="google.com"
CHECK_INTERVAL=15
FAIL_THRESHOLD=3
LOG_FILE="$HOME/vpn-watchdog/watchdog.log"

fail_count=0
already_disconnected=false

log() {
  echo "$(date '+%Y-%m-%d %H:%M:%S') $1" >> "$LOG_FILE"
}

get_vpn_service() {
  scutil --nc list | grep -i fortinet | grep -oE '[0-9A-F]{8}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{12}'
}

is_vpn_connected() {
  scutil --nc status "$1" 2>/dev/null | head -1 | grep -q "Connected"
}

check_network() {
  # Some networks block ICMP ping while regular web traffic works fine.
  # Try ping first; if that fails, confirm with a real HTTPS request before
  # calling it a drop, so a ping-blocked network doesn't trigger a false disconnect.
  ping -c 1 -t 3 "$HOST" >/dev/null 2>&1 && return 0
  curl -s --max-time 3 -o /dev/null "https://$HOST" && return 0
  return 1
}

log "watchdog started (disconnect-only, interval=${CHECK_INTERVAL}s, threshold=${FAIL_THRESHOLD})"

while true; do
  if check_network; then
    if [ "$fail_count" -gt 0 ]; then
      log "network OK again after $fail_count failed check(s)"
    fi
    fail_count=0
    already_disconnected=false
  else
    fail_count=$((fail_count + 1))
    log "network check failed (count=$fail_count)"

    if [ "$fail_count" -ge "$FAIL_THRESHOLD" ] && [ "$already_disconnected" = false ]; then
      svc=$(get_vpn_service)
      if [ -n "$svc" ] && is_vpn_connected "$svc"; then
        log "threshold reached, disconnecting VPN service $svc"
        scutil --nc stop "$svc"
        already_disconnected=true
        osascript -e 'display notification "Network dropped — VPN auto-disconnected." with title "VPN Police"' >/dev/null 2>&1
      fi
    fi
  fi

  sleep "$CHECK_INTERVAL"
done
SCRIPT_EOF

chmod +x "$WD_DIR/watchdog.sh"

cat > "$PLIST" << PLIST_EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>$LABEL</string>
    <key>ProgramArguments</key>
    <array>
        <string>/bin/bash</string>
        <string>$WD_DIR/watchdog.sh</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>StandardOutPath</key>
    <string>$WD_DIR/launchagent.out.log</string>
    <key>StandardErrorPath</key>
    <string>$WD_DIR/launchagent.err.log</string>
</dict>
</plist>
PLIST_EOF

launchctl unload "$PLIST" 2>/dev/null || true
launchctl load "$PLIST"

echo "VPN Police (disconnect-only) installed and running."
echo "Log: $WD_DIR/watchdog.log"
INSTALL_EOF
chmod +x install-disconnect-only.sh
./install-disconnect-only.sh
The Detectivefollows up

Same watch, but also reconnects once the network is back — only for the drop it caused. If your VPN normally asks for SSO or MFA on every connect, expect that same prompt here too.

# one paste — writes the file, then runs it
cat > install-auto-reconnect.sh << 'INSTALL_EOF'
#!/bin/bash
# VERSION 2 — disconnect AND auto-reconnect.
# Same drop-detection as version 1, but once the network comes back, it also
# tries to reconnect the VPN automatically — ONLY if it was this script that
# disconnected it (never touches a VPN you disconnected yourself).
#
# Caveat: if your FortiClient VPN requires SSO/MFA/2FA on every connect, the
# reconnect call may open a login prompt instead of silently succeeding —
# scutil can't complete an interactive login for you.
set -e

WD_DIR="$HOME/vpn-watchdog"
LABEL="com.vpnpolice.agent.autoreconnect"
PLIST="$HOME/Library/LaunchAgents/$LABEL.plist"

mkdir -p "$WD_DIR"
touch "$WD_DIR/watchdog-autoreconnect.log"

#!/bin/bash

HOST="google.com"
CHECK_INTERVAL=15
FAIL_THRESHOLD=3
LOG_FILE="$HOME/vpn-watchdog/watchdog-autoreconnect.log"

fail_count=0
we_disconnected_it=false

log() {
  echo "$(date '+%Y-%m-%d %H:%M:%S') $1" >> "$LOG_FILE"
}

get_vpn_service() {
  scutil --nc list | grep -i fortinet | grep -oE '[0-9A-F]{8}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{12}'
}

is_vpn_connected() {
  scutil --nc status "$1" 2>/dev/null | head -1 | grep -q "Connected"
}

check_network() {
  # Some networks block ICMP ping while regular web traffic works fine.
  # Try ping first; if that fails, confirm with a real HTTPS request before
  # calling it a drop, so a ping-blocked network doesn't trigger a false disconnect.
  ping -c 1 -t 3 "$HOST" >/dev/null 2>&1 && return 0
  curl -s --max-time 3 -o /dev/null "https://$HOST" && return 0
  return 1
}

log "watchdog started (auto-reconnect, interval=${CHECK_INTERVAL}s, threshold=${FAIL_THRESHOLD})"

while true; do
  if check_network; then
    if [ "$fail_count" -gt 0 ]; then
      log "network OK again after $fail_count failed check(s)"
    fi
    fail_count=0

    if [ "$we_disconnected_it" = true ]; then
      svc=$(get_vpn_service)
      if [ -n "$svc" ] && ! is_vpn_connected "$svc"; then
        log "attempting to reconnect VPN service $svc"
        scutil --nc start "$svc"
        osascript -e 'display notification "Network is back — reconnecting VPN." with title "VPN Police"' >/dev/null 2>&1
      fi
      we_disconnected_it=false
    fi
  else
    fail_count=$((fail_count + 1))
    log "network check failed (count=$fail_count)"

    if [ "$fail_count" -ge "$FAIL_THRESHOLD" ] && [ "$we_disconnected_it" = false ]; then
      svc=$(get_vpn_service)
      if [ -n "$svc" ] && is_vpn_connected "$svc"; then
        log "threshold reached, disconnecting VPN service $svc"
        scutil --nc stop "$svc"
        we_disconnected_it=true
        osascript -e 'display notification "Network dropped — VPN auto-disconnected." with title "VPN Police"' >/dev/null 2>&1
      fi
    fi
  fi

  sleep "$CHECK_INTERVAL"
done
SCRIPT_EOF

chmod +x "$WD_DIR/watchdog-autoreconnect.sh"

cat > "$PLIST" << PLIST_EOF

Retire The Officer

Stops whichever version is running and deletes everything it created.

# one paste — writes the file, then runs it
cat > uninstall.sh << 'INSTALL_EOF'
#!/bin/bash
# Removes either/both VPN Police versions completely.
set -e

WD_DIR="$HOME/vpn-watchdog"
LABELS=("com.vpnpolice.agent" "com.vpnpolice.agent.autoreconnect")

for LABEL in "${LABELS[@]}"; do
  PLIST="$HOME/Library/LaunchAgents/$LABEL.plist"
  if [ -f "$PLIST" ]; then
    launchctl unload "$PLIST" 2>/dev/null || true
    rm -f "$PLIST"
    echo "Removed $LABEL"
  fi
done

rm -rf "$WD_DIR"
echo "Deleted $WD_DIR"
echo "VPN Police fully uninstalled."
INSTALL_EOF
chmod +x uninstall.sh
./uninstall.sh

macOS + FortiClient only. Filed locally, per user — nothing leaves the precinct.
